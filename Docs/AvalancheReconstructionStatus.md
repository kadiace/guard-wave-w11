# Avalanche 재구성 작업 상태

## 현재 기준

중단 시점에는 눈사태 물리와 공통 HUD 연결을 구현하고 방어 배치를 비교하고 있었다. 후속 요청에 따라 클리어 전략 반복 검증을 중단하고, 스테이지 구성요소 확정과 고정 시민 전환을 우선한다.

## 구현한 구성요소

| 요소 | 구현과 책임 |
| --- | --- |
| 산과 마을 | 공유 높이장 지형, 지면 충돌체, 양쪽 골짜기와 겨울 마을 장식 |
| 눈사태 | 60×100 깊이 평균 격자, 이동·퇴적층, 마찰, 두 차례 방출, 유출과 부피 보존 검사 |
| 구조물 연동 | 콜라이더 경계 투영과 지지된 셀 기둥 점유, 밀려난 눈의 재분배·임시 보관, Rigidbody 하중과 접합 파손 |
| 고정 보호 대상 | 씬에 저장된 시민 6명, Stage의 직렬화 참조 목록, 충돌·매몰 관측과 위험 상태 |
| 건설 도구 | 방벽·받침·접합 블록 세 카드, 직접 생성, 회전·연속 배치·회수·Undo |
| 재도전 | 구조물 체크포인트 복원 또는 건설물만 초기화. 고정 시민은 유지하고 위험 이력만 초기화 |
| 공통 기능 | StageInfo의 재고·배치 시간 설정, 공통 HUD·팝업·편집 유틸리티·카메라·일시정지·클리어 기록 |
| 진입 | 씬 GUID와 빌드 등록 유지, 스테이지 선택의 Avalanche 카드 연결 |

시민 배치 카드·재고·영역 최소 인원·회수·편집 스냅샷·런타임 생성은 제거했다. 시민 데이터의 소유자는 `AvalancheStage`이며 건설 도구가 시민을 생성·삭제하지 않는다. `StageInfo.json`의 Avalanche 팔레트에는 건설 자재만 남긴다.

## 검증 범위

중단 전 Editor 수동 실행에서 시민 목표 배치, 준비 완료, 두 차례 방출, 위험 실패와 구조물 배치 복원, 자재·접합 편집 Undo를 확인했다. 당시에는 시민을 플레이어가 배치하는 규칙이었다.

- 150/270m³, 매몰 기준 0.35m의 무방벽 실행은 재해 17.1초에 시민 매몰로 실패했다. 종료 시점 부피 오차는 로그 정밀도에서 0m³였다.
- 같은 설정에서 정면 방벽 4개와 접합 블록 4개를 둔 실행은 18.4초에 실패했다. 종료 시점 살아 있는 접합은 0개, 부피 오차는 0.000031m³였다.
- V자 방벽의 클리어 여부는 확인하지 않았다. 이 결과들은 현재 고정 시민 버전의 인수 완료나 전 구간 최대 오차 측정을 의미하지 않는다.

고정 시민 전환 후 확인한 내용은 다음과 같다.

- `Assembly-CSharp-Editor.csproj` 빌드 통과: 오류 0개, 기존 경고 4개.
- 씬 파일에 시민 컴포넌트 6개와 Stage의 시민 참조 6개 저장.
- Unity Play에서 보호 대상 6명, 건설 카드 3개, 고정 시민 안내와 준비 완료 활성화 확인.
- 공통 일시정지 메뉴의 빈 배치 재시작 후에도 시민 6명과 위치 유지, 위험 표시 0으로 초기화 확인.

클리어까지의 반복 실행과 대규모 성능 측정은 이번 완료 조건에 포함하지 않는다. 검증 후에는 Play Mode를 종료했다.

## 후속 작업

1. 고정 시민과 방어 자재 역할이 확정된 뒤 클리어 가능한 배치, 우회 경로와 난이도 조정.
2. 이동·적설 표면의 시각 표현, 전용 충돌음과 위험 강조 보강.
3. 최대 재고의 Windows 플레이어 빌드 성능 및 전체 구간 최대 부피 오차 측정.

현재 눈 모델은 지면에 지지된 높이장 근사다. 공중 구조물 아래 통로, 완전한 3차원 눈 체적과 눈·Rigidbody 간 운동량의 완전 보존은 제공하지 않는다. 목표 프레임 시간과 명세의 모든 인수 항목을 통과했다고 판단하지 않는다.
