# Flood 진흙 연결 성능 분석

확인일: 2026-11-17. Unity 6000.3.28f1, Windows Editor, RTX 4060 / Direct3D 12.

## 결론

Ready 전의 통제 재현에서, 진흙 획과 트리거가 누적되면 기존 접착 대상에 대한
OnTriggerStay 검사가 반복되어 심한 프레임 저하가 발생했다. 이 조건에서는
물리 조인트 해석보다 접촉 이벤트에 포함된 스크립트 처리가 주된 비용이었다.
연결 수만으로 성능 한계를 판단하면 이 문제를 놓칠 수 있다.

## 재현 방법과 측정 범위

- Flood 씬을 Play Mode로 실행하고 준비 타이머를 일시 중지했다.
- 실제 Spawn 경로로 통나무 100개를 배치했다. 이후 이탈한 기물을 제외하고
  비교표의 네 상태는 모두 활성 기물 112개, 등록된 진흙 연결 102개였다.
- 기존 GuardWaveMudPatch.Initialize, AddPoint, FlushStrokeMesh를 호출해
  바닥에 가까운 통나무 표면에 18개 샘플로 이루어진 진흙 획을 만들었다.
  강바닥 접착을 포함하는 배치이며, 사용자 마우스 조작을 그대로 녹화한 재현은 아니다.
- 통나무당 한 획에서 다섯 획으로 겹칠을 늘리고, 같은 연결과 메시를 유지한 채
  Dry 호출 및 진흙 트리거 비활성화를 각각 비교했다.
- Ready와 유체 Step을 실행하지 않은 상태에서 심한 지연을 재현했다.
- Profiler 파일 기록은 첫 기준 캡처 후 프레임을 수집하지 못하는 문제가 발생했다.
  아래 비교는 Unity ProfilerRecorder로 Physics 및 스크립트 마커를 직접 수집했다.
  게임 프레임 진행, 카운터 유효 상태 및 실제 샘플 수를 확인했다.
- 각 비교 구간에서 카운터를 새로 시작하고 약 3초 뒤 읽었다. 시간 마커의 합계를
  실제 Physics.SendTriggerEvents 호출 수로 나눠 물리 틱당 평균을 계산했다.
  느린 조건은 렌더 프레임 수가 적으므로 안정적인 FPS나 장시간 p95로 해석하지 않는다.

## 측정 결과

| 상태 | 활성 진흙 획 수 | 물리 틱 수 | 접촉 이벤트 / 틱 | Physics.Simulate / 틱 | Relay.OnTriggerStay 호출 / 틱 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 젖은 진흙, 통나무당 한 획 | 99 | 30 | 4.825 ms | 0.079 ms | 463 |
| 젖은 진흙, 통나무당 다섯 획 | 491 | 50 | 46.220 ms | 0.278 ms | 6,762 |
| 같은 진흙을 건조 | 491 | 35 | 2.644 ms | 0.078 ms | 6,762 |
| 같은 진흙의 트리거 비활성화 | 491 | 45 | 0.179 ms | 0.082 ms | 0 |

접촉 이벤트는 Physics.SendTriggerEvents이며 진흙 콜백 실행 시간을 포함한다.
부모 이벤트 시간과 그 안의 스크립트 시간을 더하면 비용을 중복 계산하게 된다.

젖은 491획 조건에서는 4개 카운터 샘플 구간에 물리 틱 50회가 관측됐다.
Main Thread 마커의 프레임 값도 수백 ms로 증가했다. 고정 간격이 20 ms인데
접촉 처리만 틱당 46 ms가 필요하여, 밀린 물리 업데이트가 연속 실행되는 현상과
일치한다. GC와 메시 재생성만으로 이 지연을 설명할 수는 없다.

기물끼리 붙이는 49쌍 배치에서도 접촉 이벤트 약 1.57 ms/틱,
Physics.Simulate 약 0.21 ms/틱이 관측됐다. 이 배치는 접착 후 조인트 파손으로
등록 연결 수가 줄었으므로 위의 연결 수 고정 비교표에는 포함하지 않았다.

## 확인된 코드 경로

1. GuardWaveMudTriggerRelay.OnTriggerStay는 각 캡슐의 접촉을 패치로 전달한다.
   패치의 TryBond는 트리거 자체, 원래 표면, 이미 접착한 대상 등을 충분히
   앞에서 제외하지 않아 접착할 수 없는 대상도 검색에 들어갈 수 있다.
2. TryBond의 possibleCreek 경로는 획 전체 샘플을 순회한다. 동일 물리 틱의
   중복 검사 방지보다 앞에 있고, 실제 HasMudBond / WasEverMudBonded 판정은
   샘플마다 호출되는 TryBondAt 안에 있다. 이미 고정된 물체도 반복 순회한다.
3. 겹친 획은 새 트리거를 계속 만든다. 건조해도 트리거는 활성 상태여서
   Dry 이후에도 틱당 6,762회 콜백 전달이 남았다.
4. 기본 Fixed Timestep은 0.02초이고 Maximum Allowed Timestep은 약 0.333초다.
   비싼 접촉 처리가 여러 물리 틱에 반복되면 한 렌더 프레임의 지연이 확대된다.

## 권장 개선 순서

1. 접착 대상의 유효성을 샘플 검색 전에 한 번 판정한다. 트리거, 자기 표면,
   같은 Rigidbody, 비활성 대상, 이미 접착했거나 재접착할 수 없는 대상은
   기존 규칙대로 일찍 제외한다. 바닥 접착은 검사 대상이 원래 표면의 기물이고,
   일반 접착은 상대 기물이라는 차이를 유지해야 한다.
2. 바닥 특수 경로에도 패치와 상대 Collider 단위의 물리 틱 중복 방지를 적용한다.
   샘플마다 반복하는 컴포넌트 검색과 접착 가능 상태 조회도 줄인다.
3. 마른 패치의 접착 트리거를 비활성화한다. Undo, 실패 복원, 재시작에서
   젖은 상태로 복원할 때 트리거와 접촉 캐시를 함께 복원한다.
4. 진흙 전용 물리 레이어와 필요한 접촉 조합을 설정하고, 같은 표면의 겹친 획은
   접착 판정용 영역을 공유하거나 단순화한다. 눈에 보이는 획과 실제 접착 범위의
   대응을 유지하며, 새 기물의 접착 기회를 잃지 않도록 해야 한다.
5. 위 개선 후에도 움직이는 큰 연결 구조에서 Physics.Simulate가 병목이면
   Rigidbody 솔버 16/8 반복 설정을 별도로 조정한다. 이번 측정만으로 먼저
   솔버 반복 수나 Fixed Timestep을 바꿀 근거는 부족하다.

표면 기물 하나가 이미 접착됐다는 이유로 젖은 패치 전체를 끄면,
나중에 다른 기물을 붙이는 기존 동작이 달라진다. 조기 제외는 실제 접착 대상에
적용해야 한다. 건조 여부에 따른 비활성화와 젖은 패치의 대상별 제외는 구분한다.

## 추가 비용과 제한

GuardWaveStickForceProbe는 물체마다 매 물리 틱 Debug.Log를 실행한다.
첫 기준 캡처에서 이 컴포넌트는 약 1.38 ms/물리 틱 및 약 80 KB/물리 틱의
직접 GC 할당을 기록했다. 이후 위 비교는 해당 프로브를 끈 동일 조건에서 수행했다.
상시 로그를 선택형 또는 낮은 빈도의 진단으로 바꾸는 것도 별도 개선 후보다.

붓질 중 전체 메시 재생성과 붓질 종료 시 전체 Undo 스냅샷 저장 비용은 코드상
존재하지만, 이번 정지 상태 재현의 주원인으로 측정된 것은 아니다.
실제 사용자 배치와 Standalone 실행에서의 절대 성능은 추가 비교가 필요하다.

원시 측정값은 현재 작업공간의 Temp/MudDiagnostics/*.json에 보관했다.
Temp는 임시 디렉터리이므로 영구 보관 자료는 아니다.

측정 후 카운터를 해제하고 Play Mode를 종료했다. 재현용 오브젝트가 제거됐고,
Flood 씬의 미저장 변경이 없으며 원래 진단 프로브도 활성 상태로 복원된 것을 확인했다.
위 원인 분석 당시에는 코드와 씬 및 물리 설정 에셋의 최적화 변경을 적용하지 않았다.

## 수정 적용 및 Play Mode 확인

2026-11-17에 GuardWaveMudPatch.cs에 다음 변경을 적용했다.

- 접착 대상과 연결 Rigidbody를 샘플 순회 전에 한 번 결정한다. 이미 연결했거나
  재접착할 수 없는 기물, 자기 표면과 같은 Rigidbody 및 트리거는 일찍 제외한다.
- 강바닥 접촉도 동일 패치와 Collider에 대해 물리 틱당 한 번만 검사한다.
- 직접 붓질과 표면 경계 접착은 기존의 즉시 검사 경로를 사용한다.
- 활성 접착 트리거를 등록해 건조 시 끄고, 건조 상태 복원 시 함께 복원한다.
  씬에서 처음부터 비활성화된 트리거는 자동으로 켜지 않는다.
- 건조 상태를 복원할 때 접촉 검사 캐시를 비운다. 젖은 패치는 새 기물을
  계속 받을 수 있으며, 조인트의 접착 범위와 강도 및 파손 설정은 유지한다.

Unity 재컴파일은 오류 0건, 경고 0건이었다. 별도 테스트 스크립트 파일을 추가하지
않고 CLI로 Play Mode의 기존 생성·접착·복원 메서드를 실행해 다음을 확인했다.

- 이미 바닥에 연결된 표면의 젖은 진흙에 나중에 접근한 기물이 트리거로 붙었다.
- 이미 접촉 중인 기물은 AddPoint 호출 직후 붙었다.
- Dry를 두 번 호출해도 강도는 한 번만 증가했다. 재현 기물의 breakForce는
  150에서 300으로, breakTorque는 1400에서 2800으로 변했다.
- 건조 후 기존 연결은 유지됐고 새 접착은 차단됐다. 런타임 캡슐 트리거는 꺼졌다.
- 실제 UndoLastEdit 경로에서 젖은 상태, 활성 트리거와 150/1400 강도가 복원됐다.
- ConfirmFailure 경로에서 건조 상태의 비활성 트리거와 300/2800 강도,
  젖은 상태의 활성 트리거와 150/1400 강도를 각각 복원했다.
- 씬에 작성된 구형 트리거 13개도 건조 시 꺼지고 ResetDryness 시 켜졌다.
- 파손 후 같은 기물의 재접착 제한은 유지됐고, 다른 새 기물은 복원된 젖은
  진흙에 붙었다. 재시작 후 씬에 작성된 진흙의 젖은 트리거 상태도 복원됐다.

같은 방식으로 통나무와 겹친 18샘플 획을 생성하고 ProfilerRecorder로 재측정했다.
수정 전은 기물 112개·연결 102개·획 491개, 수정 후는 기물 114개·연결 106개·획
501개여서 완전히 동일한 스냅샷의 비교는 아니다. 두 측정 모두 진단 로그를 끄고
Ready 전 상태에서 약 3초 동안 수집했다.

| 상태 | 접촉 이벤트 / 물리 틱 | Physics.Simulate / 물리 틱 | 관측 물리 틱 수 |
| --- | ---: | ---: | ---: |
| 수정 전, 젖은 491획 | 46.220 ms | 0.278 ms | 50 |
| 수정 후, 젖은 501획 | 1.047 ms | 0.081 ms | 64 |
| 수정 후, 건조한 501획 | 0.051 ms | 0.078 ms | 67 |

수정 후 건조한 재현용 500획의 활성 접착 트리거 수는 0이었다. 측정값은 이 짧은
Editor 재현 구간의 결과이며, 전체 게임이나 Standalone의 성능 보장치는 아니다.
원시 값은 Temp/MudDiagnostics/after_mud500_wet.json,
after_mud500_dry.json 및 functional_*.json에 있다.

확인 후 카운터를 해제하고 Play Mode를 종료했다. 씬이나 물리 설정 에셋은
저장하지 않았으며, 이번 구현 변경은 GuardWaveMudPatch.cs에 한정된다.
