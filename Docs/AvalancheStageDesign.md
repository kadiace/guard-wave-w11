# Avalanche 스테이지 기획 명세

- 상태 — 눈사태 프로토타입 구현 사양. 구성요소를 우선 확정하며, 클리어 전략과 성능 목표의 검증은 후속 작업이다.
- 대상 — `Assets/Scenes/Avalanche.unity`
- 현재 구현 — 이동·퇴적 눈, 두 차례의 방출, 시민 충돌·매몰, 방어 구조물 편집과 공통 HUD를 사용한다. 시민은 씬에 미리 배치하며 플레이어가 옮기거나 회수하지 않는다. 조작과 튜닝 위치는 [프로토타입 안내](AvalanchePrototype.md), 작업 상태는 [재구성 기록](AvalancheReconstructionStatus.md)을 참고한다.

## 1. 목표와 플레이 경험

산기슭 마을에 미리 배치된 시민 6명을 방벽으로 두 차례의 눈사태에서 지킨다. 눈을 받아 내거나 우회시키기 위해 눈의 진행 방향, 구조물의 지지와 접합, 시민 주변의 여유 공간을 함께 고려한다. 첫 눈사태가 남긴 퇴적과 방벽 상태는 두 번째 눈사태에도 유지된다.

배치 제한시간은 없다. 방어 구조물을 설치하고 준비 완료를 누르면 경보와 재해가 시작된다. 시민 한 명이 위험 조건에 도달하면 실패한다. 대피·배수 지정과 목표 깃발은 사용하지 않는다. 이 고정 시민 규칙은 Avalanche에만 적용한다.

## 2. 지형과 시민 배치

좌표는 Unity 월드 좌표다. 지도는 X -18~18m, Z 0~60m이며 북쪽 +Z에서 남쪽 -Z 방향으로 눈이 이동한다. 0.6m 간격, 60 × 100 셀을 사용한다. 지형 높이와 격자 바닥, 렌더링 메시, 지면 콜라이더는 같은 높이 데이터를 사용한다.

첫 회색 박스의 중앙 기준 높이는 다음과 같다. 구간 경계의 기울기는 1.2m 폭으로 부드럽게 연결하며, 실제 높이와 기울기는 Inspector에서 조정한다.

| Z 범위 | 높이 시작값 | 역할 |
| --- | --- | --- |
| 0~24m | `0.02 × Z`m | 마을과 남쪽 완경사 |
| 24~42m | `0.48 + 0.12 × (Z - 24)`m | 방벽을 설치하는 중앙 사면 |
| 42~60m | `2.64 + 0.36 × (Z - 42)`m | 발원부와 급경사 |

서쪽과 동쪽의 빈 골짜기는 각각 X -11m, +11m를 중심으로 중앙 사면보다 최대 0.8m 낮게 만든다. 폭은 중심에서 좌우 3m를 시작값으로 하고, 마을과 맵 경계에서는 지형이 급격히 꺾이지 않도록 연결한다. 장식 건물은 흐름을 막는 장애물이 아니며, 플레이어에게 골짜기와 마을을 구분해 보여 준다.

시민은 `Protected citizens` 아래 실제 씬 오브젝트로 저장한다. 산장·광장·정류장에 각 2명씩 둔다. 디자이너는 씬의 Transform과 `AvalancheStage > Citizens` 참조 목록에서 위치와 인원을 편집한다. 런타임 배치 카드, 시민 재고, 영역별 최소 인원 판정은 사용하지 않는다.

| 구역 | 기본 시민 위치 X, Z |
| --- | --- |
| 서쪽 산장 | (-4, 14), (-4, 18) |
| 중앙 광장 | (0, 14), (0, 18) |
| 동쪽 정류장 | (4, 14), (4, 18) |

구조물 콜라이더와 시민 중심 사이에는 수평 0.6m의 여유를 둔다. 이 값은 Construction Inspector에서 조정한다. 시민은 고정된 위치에서 눈을 관측하며 흐름을 막거나 Rigidbody로 밀리지 않는다. 씬에서 위치를 수정할 때는 시민 발과 주변 관측 지점이 지형과 계산 격자 안에 있도록 배치한다.

시민 목록은 보호 대상과 구역명, 현재 적설 및 충돌·매몰 시간을 표시한다. 시민이 한 명 이상 씬 참조 목록에 있으면 준비 완료를 사용할 수 있다. 재도전과 빈 배치 초기화는 시민 오브젝트를 유지하고 위험 상태만 초기화한다. Undo는 플레이어가 설치한 구조물과 접합에만 적용한다.

발원부 Z 48m 이상 60m 이하는 자재를 배치할 수 없다. 자재는 X -17.4~17.4m, Z 1m 이상 48m 미만의 지면과 다른 자재 위에 놓을 수 있다. 지형·기존 자재와의 충돌 및 시민 여유 공간은 배치 전에 검사하고, 유효하지 않은 이유를 표시한다.

## 3. 팔레트와 조작

| 항목 | 첫 수량 | 역할 |
| --- | --- | --- |
| 유도 방벽 `panel` | 12 | 크기 3.6 × 1.2 × 0.6m. 높은 판으로 눈을 막거나 사선으로 유도한다. |
| 하중 받침 `sandbag` | 10 | 크기 1.4 × 0.55 × 1.1m. 방벽 뒤 지지와 낮은 틈 보강에 사용한다. |
| 접합 블록 `adhesive` | 18 | 클릭당 1개. 지면 또는 자재에 붙이고 닿은 자재를 기존 경화 접합 강도로 즉시 연결한다. 회수하면 해당 접합을 해제한다. |

수량은 `StageInfo.json`에 두고 크기·질량·마찰·접합과 눈의 물리 수치는 씬 Inspector에서 조정한다. 접합은 기존 공통 `StageJoint`와 Avalanche의 연결·파손 규칙을 사용하며 파손된 연결은 자동으로 복구하지 않는다.

다른 스테이지의 `GuardWaveHud`를 기준으로 카드의 이름·아이콘·남은 수량·선택 강조, 준비 완료·규칙·결과 팝업, 배치 미리보기 색을 일관되게 제공한다. Avalanche는 건설 카드 세 개를 사용하고 시민은 왼쪽 보호 대상 목록에 표시한다. 다른 스테이지의 목표물 배치 카드는 유지한다.

| 입력 | 동작 |
| --- | --- |
| 카드 선택 후 왼쪽 클릭 | 미리보기 위치와 회전에 자재를 직접 생성한다. 접합 블록은 클릭한 표면에 설치한다. |
| 왼쪽 버튼 드래그 | 방벽·받침은 겹치지 않는 위치마다 연속 배치한다. 접합 블록은 클릭당 하나씩 배치한다. |
| `Q` / `E` | 선택한 자재 회전. 접합 블록에는 적용하지 않는다. |
| 우클릭 짧게 | 선택 중이면 선택을 취소한다. 선택이 없으면 가리킨 배치물을 하나 회수한다. 빈 곳이면 팔레트를 연다. |
| 우클릭 드래그 | 카메라 평행 이동. 짧은 클릭과 구분하여 선택 취소·회수가 일어나지 않는다. |
| 휠 / 우클릭 중 휠 | 확대·축소 / 카메라 회전. UI 위에서는 카메라와 배치 입력을 받지 않는다. |
| `Ctrl+Z` | 마지막 자재·접합 블록 배치 또는 회수와 그에 따른 재고·접합을 복원한다. |
| `Esc` | 선택 중이면 선택을 취소하고, 선택이 없으면 공통 일시정지 메뉴를 연다. |
| 시민 목록 클릭 / `Home` | 해당 시민에게 카메라 초점 이동 / 전체 보기. 시민이 없는 구역 버튼은 두지 않는다. |

준비 완료 후에는 배치·회수·Undo를 잠그되 카메라와 일시정지는 허용한다. 포인터가 팝업이나 UI 위에 있을 때 월드 오브젝트를 조작하지 않는다. 기존 Avalanche의 우클릭 회전·가운데 버튼 이동은 위 공통 입력에 맞게 변경한다. 카메라 범위와 확대 한계는 씬에서 설정한다.

## 4. 재해 진행과 시민 판정

시간 `t`는 **5초 경보가 끝난 직후 0초**부터의 게임 시뮬레이션 시간이다. 일시정지 중에는 경보, 눈과 시민 판정 시간이 모두 멈춘다. 준비 완료 직전에 자재의 위치와 자세, 속도, 재고, 접합 및 연결 상태를 저장한다. 시민은 씬의 고정 목표다.

| 시점과 단계 | 처리 |
| --- | --- |
| 준비 | 씬에 등록된 시민을 보호할 구조물을 설치한다. 시민 재고나 영역별 최소 인원 조건은 없다. 제한시간 없이 준비 완료로 시작한다. |
| 경보 | 준비 완료 후 5초. 발원부와 예상 방향을 강조하고 편집을 잠근다. |
| 첫 방출 | `t = 0초`에 첫 눈을 발원 영역에 한 번에 추가한다. |
| 두 번째 방출 | `t = 12초`에 두 번째 눈을 추가한다. 첫 눈과 퇴적, 방벽의 변화는 유지한다. |
| 안정 관찰 | 두 번째 방출이 완료되고 `t ≥ 20초`인 때부터 성공 조건의 연속 시간을 계산한다. 조건이 하나라도 깨지면 0초로 초기화한다. |
| 종료 | 시민 실패를 먼저 판정한다. 실패가 없고 성공 조건이 충족되면 성공한다. `t = 60초`에도 성공하지 못하면 잔류 위험 또는 미안정으로 실패한다. 정확히 60초에 성공 조건이 충족되면 성공을 우선한다. |

각 시민의 발 위치와 수평 반경 0.4m의 네 방향, 총 다섯 지점에서 0.1초마다 이동층 두께·속도와 정지층 두께를 읽는다. 시민과 관측 지점이 계산 영역 안에 있도록 씬을 구성한다. 샘플의 총 적설은 이동층과 정지층 두께의 합이다. 시민 위치는 고정되고 눈의 렌더링 파티클은 판정에 쓰지 않는다.

- **충돌:** 다섯 지점 중 2개 이상에서 이동층 두께가 0.35m 이상이고 속도가 2m/s 이상이면 해당 시민의 충돌 노출 시간을 누적한다. 조건이 사라지면 누적을 멈추며, 충돌 조건이 없는 상태가 2초 연속 지속될 때 누적을 0으로 초기화한다. 그 전에 조건이 다시 생기면 기존 누적값부터 더한다. 누적 1.5초 이상이면 실패한다.
- **매몰:** 다섯 지점 중 2개 이상에서 총 적설 두께가 0.35m 이상이면 매몰 시간을 누적한다. 조건이 한 번이라도 사라지면 즉시 0으로 초기화하며, 2초 연속이면 실패한다. 이는 실제 인체 매몰 기준이 아닌 게임의 조정 가능한 시작값이다.
- 매 샘플에서 조건을 충족하는 지점의 조합은 달라도 된다. 시민별 충돌·매몰 시간을 따로 계산하고, 충돌 0.75초 또는 매몰 1초부터 경고한다. 두 실패 조건이 같은 샘플에서 성립하면 매몰을 원인으로 표시하고, 여러 시민이 동시에 실패하면 씬의 시민 Objective ID가 작은 순서로 대표 원인을 표시한다.
- **시민 안전:** 현재 충돌 조건과 매몰 조건이 모두 없고 충돌 누적 시간이 0이어야 한다. 시민별 안전 상태와 전역 눈 안정 조건이 함께 3초 연속 유지돼야 성공한다.

전역 눈 안정 조건은 속도 0.25m/s 이상인 셀에 남은 이동층 부피와 이동층 임시 보관량의 합이 **두 방출의 총량 420m³의 1% 미만**, 즉 초기값 기준 4.2m³ 미만인 상태다. 방출량을 조정하면 분모도 조정된 두 방출량의 합을 따른다. 정지층과 유출량은 분자에 포함하지 않는다. 방출 전에는 안정 판정을 하지 않는다.

결과 화면에는 충돌·매몰 실패의 첫 시민과 원인·시각을 표시한다. 시간 초과는 특정 실패 시민 없이 잔류 위험 또는 미안정을 원인으로 표시한다. 실패와 기술 오류에서는 준비 완료 직전 구조물 배치로 돌아가 수정하거나 빈 배치로 다시 시작할 수 있다. 배치 복원은 자재·재고·자세·속도·접합을 복원하고, 눈·판정 시간·시민 위험도를 초기화한다. 빈 배치는 플레이어가 설치한 자재와 접합 블록만 지운다. 시민은 두 경우 모두 유지한다. 성공은 `StageClearSession`에 기록한다.

## 5. 눈사태 물리의 첫 구현값

물과 다른 테마에 맞춰 조밀한 눈을 깊이 평균 입상체 격자로 근사한다. 각 셀은 이동층 두께와 수평 운동량, 정지층 두께를 가진다. 아래 수식과 숫자는 게임 플레이를 위한 초기 모델이며 현실 예측값이 아니다. 눈가루와 균열 전파는 시각 연출만 담당한다. 참고: [Pouliquen·Forterre의 입상체 마찰 실험](https://doi.org/10.1017/S0022112001006796), [Christen 등의 깊이 평균 눈사태 모델](https://doi.org/10.1016/j.coldregions.2010.04.005), [Cui 등의 유도 방벽 연구](https://doi.org/10.1029/2006JF000712).

| 항목 | 첫 설정과 처리 |
| --- | --- |
| 초기 상태 | 눈은 0m³이며 표면의 장식용 눈과 판정용 눈을 분리한다. 눈 밀도는 300kg/m³, 중력은 9.81m/s²로 시작한다. |
| 발원 | 첫 중심 X -2m, Z 52m, 150m³. 두 번째 중심 X 2m, Z 52m, 270m³. 두 영역 모두 X 반경 3.6m, Z 반경 4.8m인 타원이다. 중심이 두껍고 가장자리가 0인 `max(0, 1-r²)` 가중치를 셀 중심에 적용하고, 각 셀의 부피 합이 지정 총량이 되도록 정규화한다. 정해진 시각에 한 번에 주입하며 초기 수평 속도는 `(0, -1)`m/s다. 발원 영역을 미리 화면에 표시한다. |
| 이동과 마찰 | 경사 방향 중력과 이동 마찰 계수 0.18을 적용한다. 셀 경계를 지나는 유량으로 이동층 부피와 운동량을 함께 옮기며 음수 두께를 허용하지 않는다. 마찰로 속도 방향이 반전되지 않도록 0에서 멈춘다. |
| 퇴적 | 셀의 이동 속도가 0.25m/s 미만이고 지면 기울기의 탄젠트가 정지 마찰 계수 0.30 이하인 상태가 0.5초 연속이면, 이후 초당 남은 이동층의 50%를 정지층으로 옮긴다. 분할 시간 `Δt`에 옮기는 비율은 `1 - exp(-ln(2) × Δt)`다. 조건이 깨지면 대기 시간을 초기화한다. 퇴적 조건을 만족하는 셀의 잔여 이동층이 0.005m 미만이면 전부 정지층으로 옮긴다. 이 첫 버전에서 정지층은 재유동하지 않으며 높이를 바닥에 더해 다음 눈의 흐름과 방벽 하중에 반영한다. |
| 방벽 투영 | 콜라이더의 실제 위치와 자세를 격자 경계에 투영해 통과 높이를 만든다. 얇은 방벽도 교차한 경계를 막으며 눈이 상단을 넘거나 끝을 돌아 우회할 수 있다. 활성 자재의 목록·위치·자세가 바뀌면 전체 투영을 갱신하고, 그대로면 캐시를 사용한다. 지면과 아래 자재에 지지된 셀 기둥의 점유 높이도 분리한다. 이는 공중 구조물 아래 공간까지 재현하는 3차원 체적 모델은 아니다. |
| 눈과 자재의 하중 | 방벽의 눈을 향한 면에서 상대 속도의 면 법선 성분을 `v`, 접촉한 눈 높이를 `h`, 면 법선에 수직으로 투영한 접촉 면적을 `A`라 한다. 면별 하중 크기는 `A × (ρ × v² + 0.5 × K × ρ × g × h)`이고 초기 정지층 압력 계수 `K = 0.4`다. 압력은 눈이 더 높은 쪽에서 낮은 쪽으로 작용한다. 면별 힘을 접촉 높이의 중간에 적용하고 한 Rigidbody에 가하는 눈 하중 합은 초기 12,000N으로 제한한다. 접합 파손은 공통 조인트의 힘·토크 한계로 결정한다. 이 힘 모델은 게임용 근사이며 격자와 Rigidbody 사이의 운동량을 완전히 보존한다고 가정하지 않는다. |
| 경계 | 남쪽 Z=0은 열린 유출 경계이며 나간 이동층 부피를 기록한다. 북쪽 Z=60과 양쪽 X 경계는 닫혀 있어 법선 방향 유량이 0이다. 정지층은 경계를 통과하지 않는다. |
| 부피와 안정성 | 저장량은 이동층 + 정지층 + 누적 유출량이고 기대량은 실제 누적 주입량이다. 주입 이후 매 물리 단계의 부피 오차가 두 방출 총량의 1%를 넘거나 NaN·음수 두께가 발생하면 기술 오류로 중지한다. 판정용으로 소량을 무단 삭제하지 않는다. |

장애물의 이동으로 셀에서 사용할 수 없는 공간이 생기면 영향을 받은 눈을 열린 인접 셀에 나누어 옮긴다. 정지층은 옮긴 뒤에도 정지층으로 유지하며 속도를 부여하지 않는다. 이동할 곳이 없으면 이동층과 정지층을 각각 해당 셀에 임시 보관하고 다음 단계에 다시 분배한다. 보관량은 저장량과 해당 위치의 시민 적설 판정·방벽 하중에 포함하며, 이동층 보관량은 안정 판정의 이동층 부피에도 포함한다. 주입 지점이 막힌 경우에도 주입량을 잃지 않도록 같은 보관 규칙을 적용한다.

눈 이동은 60×100 높이 격자에서 표면 높이와 방벽 능선을 비교해 낮은 이웃 셀로 분배하는 게임플레이 중심 규칙 모델로 계산한다. 솔버는 0.05초 간격으로 한 번만 실행하며, 셀은 한 틱에 이동층의 최대 45%까지만 내보낸다. 유량 반응 계수는 3/s, 시민·구조물 판정에 쓰는 유속은 14m/s로 제한한다. 따라서 CFL 기반 시간 분할 횟수 제한은 두지 않는다. 눈 부피 오차 1%와 비정상 수치 검사는 유지해 부피 보존 오류나 유효 범위를 벗어난 값은 기술 오류로 처리한다.

기존 `AvalancheWater`의 격자 인덱싱·표면 메시·위치 샘플링·장애물 후보 수집은 검토 후 재사용한다. 물의 유입·배수, 부력과 수압 계산은 눈 전용 모델로 교체한다. 유동층·정지층 상태, 마찰·퇴적·하중 및 시민 판정은 Avalanche 씬 로직이 소유한다. 주요 초기값과 판정 기준은 씬 Inspector에서 조정할 수 있게 한다.

## 6. 화면과 다른 스테이지의 공통 구조

| 구성 | 적용 방식 |
| --- | --- |
| 스테이지 데이터 | `GuardWaveStageInfoFile`로 재해명·건설 재고·준비 시간을 읽는다. 재해명은 `눈사태`, 팔레트는 건설 자재 세 개다. 시민은 배치 재고가 아니므로 `StageInfo.json`에서 제거하고 씬의 `AvalancheStage > Citizens`가 관리한다. 다른 스테이지의 공통 목표 배치 판정은 유지한다. |
| HUD | 공통 `GuardWaveHud`의 카드·준비 완료·규칙·결과 화면을 씬별 상태와 명령에 연결할 수 있도록 분리한다. 현재 `GuardWaveGame`과 Fog 전용 참조를 직접 넘기지 않는다. 기존 Flood·Fog·Lava의 카드·입력·팝업 동작은 유지한다. |
| 상태와 명령 | 화면은 카드 ID·이름·아이콘·잔량·선택 상태, 준비 가능 여부, 재해 단계·결과를 읽는다. 카드 선택·준비 완료·규칙 열기·재도전·메뉴 복귀를 씬 로직에 요청한다. 고정 시민별 구역과 위험은 Avalanche 전용 목록으로 제공한다. |
| 배치와 편집 | 공통 `StagePlacement`, `StageEditHistory`, `StageJoint`를 사용한다. Avalanche가 자재 충돌·시민 여유 공간·접합 상태와 눈 위험을 담당한다. 공통 팔레트의 다섯 칸 중 세 건설 항목을 표시한다. |
| 시간·일시정지·카메라 | `StagePreparationClock`, `StagePauseMenu`, `StageCameraController`를 재사용한다. 기본 배치 시간 제한은 끄고, 5초 경보와 최대 60초 재해 관찰은 Avalanche에 둔다. 공통 입력에 맞추면서 시민 집중과 전체 보기는 추가 제공한다. |
| 진입·클리어 | 빌드 등록과 `Scene.Avalanche`, `StageClearSession`은 이미 있다. `Game.unity` 포스터 캐러셀에 네 번째 카드를 추가하고 `OutGameStageSelect`의 씬·제목·설명·이미지와 클리어 배지를 연결한다. 포스터 제목은 `WHITE DESCENT`를 시작안으로 한다. |

전역 씬 이동은 `Managers.Scene`을 사용한다. 공통 화면은 화면에 필요한 값과 명령만 알고, 눈 계산이나 시민 위험 규칙을 소유하지 않는다. 기존 공통 스테이지의 물리와 규칙을 눈사태에 맞춰 바꾸지 않는다.

## 7. 시각과 소리

흐린 겨울 낮의 산간 마을을 기본 톤으로 한다. 회청색 능선, 밝은 설면, 어두운 소나무와 따뜻한 목조 건물로 지형과 마을을 구분한다. 이동층은 움직이는 불규칙한 전면, 정지층은 무광의 남은 능선으로 표현한다. 눈가루는 시야와 UI를 가리지 않는다.

발원부·예상 방향·고정 시민 위치·배치 금지 영역은 준비 단계에서 읽을 수 있어야 한다. 시민 위험은 색뿐 아니라 충돌·매몰 문구와 수치로 표시한다. 실패 시 마지막 위험 시민과 원인을 표시한다. 기본 경보와 방출은 낮은 진동음으로 전달한다. 별도의 충돌음과 눈가루 연출은 후속 표현 보강 항목이다.

## 8. 구현 순서와 인수 기준

아래 항목은 최종 인수 목표다. 이번에는 구성요소와 고정 시민 연결을 우선하며, 반복 클리어와 성능 검증은 후속 단계로 남긴다. 확인한 결과는 재구성 기록에 구분해서 적는다.

1. **회색 박스:** 위 지형과 발원부를 만들고 시민을 `(-4,14)`, `(-4,18)`, `(0,14)`, `(0,18)`, `(4,14)`, `(4,18)`의 XZ에 배치한다. 첫 도착은 Z 13~20m인 셀에서 이동층 두께가 처음 0.05m 이상이 되는 시점과 해당 셀 중심으로 정의한다. 자재가 없는 같은 초기 상태에서 세 번 실행해 첫 도착 위치 차이가 한 셀 0.6m 이내, 첫 도착 시각 차이가 0.2초 이내인지 확인한다. 이 배치에서 눈이 마을에 도달하고 시민 위험이 발생해야 한다. 차이가 크거나 눈이 도달하지 않으면 통과로 간주하지 않는다.
2. **방벽과 퇴적:** 위 시민 배치에서 자재 없이 진행한 경우와 정면 방벽·사선 방벽을 놓은 경우를 비교한다. 사선 방벽 뒤의 눈 경로 변화, 정면 방벽 앞 퇴적, 방벽 파손 후 열린 경계와 첫 방출의 퇴적이 두 번째 방출까지 유지되는지 확인한다. 자재가 움직여도 눈 부피와 유출 기록이 유지되어야 한다.
3. **퍼즐과 재도전:** 클리어 전략 비교와 난이도 조정은 구성요소 확정 후 수행한다. V자 유도와 한쪽 우회·보조 방벽을 구성해 결과를 기록한다. 충돌·매몰·시간 초과·동시 실패 우선순위를 확인한다. 회수·Undo·배치 복원·빈 배치 초기화가 고정 시민을 삭제하거나 옮기지 않아야 한다. 재도전은 시민 위험만 초기화하고 자재·접합은 선택한 초기화 방식에 따라 처리한다.
4. **공통 화면과 진입:** 스테이지 선택 → 준비 → 결과 → 스테이지 선택 흐름과 위 입력을 확인한다. 무제한 준비에서 자동 시작하지 않고 일시정지 중에는 경보·눈·판정이 멈춰야 한다. Flood·Fog·Lava에서 카드, 우클릭, 준비 완료, 결과 화면이 이전과 동일하게 작동해야 한다.
5. **물리와 성능:** 매 실행의 최대 부피 오차를 기록하고 두 방출 총량의 1% 미만이어야 한다. 최대 재고와 두 번째 방출을 포함한 20초 구간을 Windows 1080p 플레이어 빌드에서 측정한다. 기준 사양은 6코어 3GHz급 CPU, 16GB RAM, GTX 1060 6GB급 GPU를 시작안으로 기록하며, 해당 구간 프레임의 95%가 16.7ms 이내인 것을 목표로 한다. 실제 CPU·GPU·품질 설정·측정 결과를 함께 남긴다. 준비 단계에는 눈 이동 계산을 실행하지 않는다.
