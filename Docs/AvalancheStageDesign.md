# Avalanche 스테이지 기획 명세

- 상태 — 구현 전 제안. 아래 수치는 첫 플레이 검증에 사용할 시작값이다.
- 대상 — `Assets/Scenes/Avalanche.unity`
- 현재 구현 — 두 차례의 홍수와 시민 노출을 계산하는 프로토타입. 대피·배수 지정은 이미 제거됐으며, 기존 구현과 관측 기록은 [Avalanche 프로토타입](AvalanchePrototype.md)에 있다.

## 1. 스테이지 목표

**산기슭 마을에 시민 6명을 직접 배치하고 방벽으로 눈의 진행 방향을 바꿔 두 차례의 눈사태에서 지킨다.**

플레이어가 판단할 것은 눈을 어디서 받을지, 어느 방향으로 보내고, 어느 방벽에 지지대를 쓸지다. 비스듬한 방벽은 눈을 옆으로 보내지만 출구가 좁으면 끝에 눈이 쌓인다. 정면 방벽은 한동안 눈을 가둘 수 있으나 쌓인 눈이 높아지면 다음 눈사태가 방벽을 넘거나 접합을 끊는다. 첫 번째 눈사태에서 생긴 적설과 구조물 변화가 두 번째 눈사태의 경로를 바꾼다.

시민은 공통 스테이지 설정에 등록된 필수 목표물이다. 플레이어가 시민 전원을 직접 배치한 뒤 준비를 완료한다. 대피·배수 지정은 설계 범위에서 제외한다.

## 2. 지형과 자재

첫 회색 박스 지도는 기존 씬의 36 × 60m 범위를 출발점으로 삼는다. 화면 상단 북쪽에서 눈이 떨어져 남쪽으로 흐른다. 가파른 발원부, 구조물을 놓는 중간 경사, 흐름이 느려지고 눈이 쌓이는 마을 앞 완경사로 나눈다.

```text
                북쪽 높은 능선 · 발원부 2곳
                             ↓
                 중앙 사면 · 1차 방어 구간
                  ↙          ↓          ↘
           서쪽 빈 골짜기    산장      동쪽 빈 골짜기
                  ↓       광장 · 정류장       ↓
             하류 경계      보호 구역      하류 경계
```

| 구역 | 배치와 플레이 목적 |
| --- | --- |
| 발원부 | 북쪽 끝. 두 눈덩이의 위치와 진행 방향을 준비 단계에서 표시하고 자재 배치를 막는다. 첫 덩어리는 좁게, 두 번째는 조금 더 넓고 옆으로 치우쳐 떨어지게 한다. |
| 중앙 사면 | 주 흐름이 모이는 곳. 정면 방벽으로 적설을 받아 내거나 비스듬히 세워 양옆 골짜기로 보낼 수 있다. 양쪽 끝의 여유 공간도 카메라에서 확인할 수 있어야 한다. |
| 마을 | 산장, 광장, 정류장을 높이와 좌우 위치가 다른 세 구역에 둔다. 시민 주변은 구조물 설치를 막고, 외곽에는 낮은 보조 방벽을 놓을 공간을 둔다. 시민은 허용된 빈 지면에 직접 배치한다. |
| 빈 골짜기 | 우회한 눈이 지나가거나 쌓이는 공간. 강제로 눈을 흡수하는 효과 없이 지형과 마찰로 감속시키고, 경계 밖으로 나간 눈의 양을 기록한다. |

| 팔레트 | 초기 수량 | 역할과 약점 |
| --- | --- | --- |
| 유도 방벽 `panel` | 12 | 높고 얇은 판. 사선으로 두면 눈을 우회시키기 쉽다. 접합이나 받침이 부족하면 밀리거나 쓰러진다. |
| 하중 받침 `sandbag` | 10 | 낮고 무거운 받침. 방벽 뒤를 지지하거나 아래 틈을 줄인다. 단독으로 놓으면 눈이 쉽게 넘어갈 수 있다. |
| 접합 블록 `adhesive` | 18 | 한 번 클릭할 때 한 개를 사용한다. 지면 또는 자재와 접촉할 때 즉시 접합하며 회수하면 재고와 연결을 함께 정리한다. |
| 보호할 시민 `citizen` | 6 | 공통 설정의 필수 목표. 허용된 빈 지면에 놓고 준비 완료 전에 회수하거나 재배치할 수 있다. 방벽 계산에는 포함하지 않는다. |

표의 이름은 플레이어에게 보이는 이름이다. 기존 자재 ID를 유지하고 눈사태용 외형·치수·질량을 별도로 설정한다. 방벽과 받침은 미리보기 위치와 회전으로 직접 설치한다. 불가능한 위치에는 미리보기 색과 함께 시민 공간, 경사, 충돌, 재고 중 막힌 이유를 표시한다.

## 3. 플레이 흐름과 판정

| 단계 | 플레이어 경험과 처리 |
| --- | --- |
| 안내·준비 | 처음에 마을, 두 발원부, 빈 골짜기를 한 화면에 보여준다. 배치 제한시간은 기본적으로 없다. 시민과 자재를 놓고 회수·되돌리기를 할 수 있다. 시민을 모두 배치해야 준비를 완료할 수 있다. |
| 경보 | 준비 완료 시 배치와 접합 상태를 저장하고 편집을 잠근다. 5초간 발원부와 흐름 방향을 표시한다. 카메라 탐색과 일시정지는 가능하다. |
| 눈사태 진행 | 경보 종료 직후 첫 눈덩이가 떨어지고, 시뮬레이션 시간 12초에 두 번째가 떨어진다. 첫 충돌에서 방벽 파손과 눈의 쌓임을 읽을 수 있게 파손 지점과 시민 위험을 표시한다. |
| 잔류 판정 | 두 번째 방출 이후 속도 0.25m/s 이상인 셀의 이동층 부피 합이 총 방출량의 1% 미만이고, 시민이 안전한 상태가 3초 연속이면 성공한다. 경보가 끝난 시점부터 60초 안에 종료 조건을 충족하지 못하면 남은 위험과 위치를 결과에 표시해 실패 처리한다. |
| 결과·재도전 | 실패 시 최초 실패 대상, 시각, 충돌·매몰 중 원인을 표시한다. 배치 복원은 준비 완료 직전의 시민·자재 자세·속도·재고·접합을 복원하고 눈과 판정 시간을 초기화한다. 빈 배치 재시작에서는 시민도 다시 놓는다. 성공은 공통 클리어 세션에 한 번 기록한다. |

시민 위험은 기존 위치 샘플링 방식을 재사용한다. 한 시민의 발 주변 다섯 지점에서 움직이는 눈 두께, 속도, 정지한 적설 깊이를 읽는다. 충돌 노출은 같은 지점에서 움직이는 눈이 **0.35m 이상이고 2m/s 이상**인 샘플이 2개 이상이면 누적한다. 누적 1.5초에 도달하면 실패한다. 매몰은 이동층과 정지층을 합한 깊이가 **0.6m 이상**인 샘플이 2개 이상에서 2초 연속이면 실패한다. 어느 한 시민이라도 실패하면 즉시 결과로 전환한다. 경고는 기준에 가까워질 때 표시하며, 실패 원인 판정에는 연출용 눈가루를 사용하지 않는다.

정지 판정 시점에는 시민에게 충돌·매몰 노출이 없어야 한다. 숫자는 모두 게임 밸런스 값으로 Inspector에서 조정한다.

첫 시도에서는 계곡을 가로지르는 일자 방벽을 놓기 쉽다. 첫 눈사태를 버텨도 중앙에 모인 눈이 두 번째에 방벽을 넘으면, 실패 화면에서 쌓인 높이와 넘은 지점을 확인할 수 있다. 다음 시도에서는 좌우로 눈을 나누는 V자 방벽을 만들거나, 한쪽 골짜기로 흐름을 보내고 마을 앞에 보조 방벽을 둘 수 있다. 두 방식이 모두 통과할 수 있는 지도와 자재 수량을 목표로 한다.

## 4. 눈사태 물리와 구현 구조

경사면을 따라 움직이는 조밀한 눈을 **깊이 평균 격자**로 표현한다. 격자 위의 유동층은 두께와 XZ 방향 운동량을 가지며, 속도가 충분히 낮아진 눈은 정지층으로 옮겨 쌓는다. 거친 경사면의 입상체 마찰과 눈사태가 사선 장애물을 따라 모이거나 두꺼워지는 관측을 참고했다. 아래 규칙은 그 차이를 플레이에서 읽을 수 있도록 만든 근사다. [Pouliquen·Forterre의 입상체 마찰 실험](https://doi.org/10.1017/S0022112001006796) · [Christen 등의 깊이 평균 눈사태 모델](https://doi.org/10.1016/j.coldregions.2010.04.005) · [Cui 등의 유도 방벽 연구](https://doi.org/10.1029/2006JF000712)

| 처리 | 첫 구현 명세 |
| --- | --- |
| 발원과 이동 | 0.6m 간격 60 × 100 셀에서 시작한다. 두 발원부에 정해진 부피의 눈을 각각 한 번 배치해 경사 방향으로 흘린다. 부피 시작값은 약 50m³와 90m³다. `FixedUpdate`에서 속도와 셀 크기에 따라 나눠 계산하고, 이웃 셀 사이로 이동할 때 질량과 운동량을 함께 갱신한다. |
| 감속과 퇴적 | 경사 방향 중력과 바닥 마찰을 적용한다. 이동 중 마찰과 정지 상태를 유지하는 역치를 별도로 두고, 속도가 낮은 상태가 일정 시간 지속되면 지형이 받쳐 주는 셀에서 이동층 일부를 정지층으로 옮긴다. 정지층 높이는 다음 흐름이 넘어야 할 바닥 높이에 포함한다. 첫 구현에서 퇴적층은 재유동시키지 않는다. |
| 방벽과 눈 | 물리 콜라이더를 격자에 투영해 셀 경계별 통과 높이를 만든다. 눈은 낮은 끝으로 돌아가고, 눈 표면이 방벽 상단을 넘으면 월류한다. 방벽이 쓰러지거나 이동하면 투영을 갱신한다. 장애물이 생겨도 해당 셀의 눈이 사라지지 않도록 질량을 보존한다. |
| 눈과 물체 | 방벽에 들어오는 면의 속도와 접촉 높이로 충돌 하중을 계산하고 실제 Rigidbody 접촉 높이에 힘을 준다. 느린 눈이 벽 한쪽에 두껍게 쌓인 경우는 좌우 높이 차에 따른 하중으로 처리한다. 방벽과 받침은 중력·마찰·접합으로 버티며 기존 `StageJoint`의 파손 한계를 사용한다. |
| 시각과 판정 | 표면 메시로 움직이는 눈과 퇴적층을 표시한다. 눈가루와 작은 눈덩이 파티클은 충돌과 매몰 판정에 관여하지 않는다. 시민·방벽과 HUD는 같은 격자에서 값을 읽는다. |
| 수치 안정성 | 음수 두께와 비정상 값, 분할 계산 상한 초과를 감시한다. 입력·유출·이동층·정지층을 합산해 질량 오차를 기록한다. 계산이 중단되면 장면을 정지하고 기술 오류와 배치 복원 선택지를 제공한다. |

기존 `AvalancheWater`에서 격자 인덱싱, 표면 메시, 위치 샘플링과 장애물 후보 수집을 검토해 재사용한다. 눈 전용 격자 상태와 마찰·퇴적·하중은 씬 전용 계산으로 분리한다. `AvalancheTerrain`의 높이 함수, 렌더링 메시와 지면 콜라이더는 같은 높이 데이터를 사용한다. `AvalanchePiece.ApplyWater`의 부력·수압은 눈 하중으로 교체한다. 눈의 파단 시점은 시나리오가 정하며 공중에 뜬 눈가루와 적설층의 균열 전파는 물리 계산 범위에서 제외한다.

구역별 경사, 발원 위치·부피·시각, 마찰·감속·퇴적 기준, 하중과 판정 역치는 씬 컨텍스트 Inspector에서 조정한다. 격자와 콜라이더가 일치하는지 회색 박스에서 먼저 확인하고, 셀 크기보다 얇은 방벽도 흐름을 가로막도록 경계 투영을 검증한다.

## 5. 디자인 톤

- **지형과 조명** — 흐린 겨울 낮의 산간 마을. 회청색 바위 능선과 밝은 설면을 구분하고, 어두운 소나무와 따뜻한 목조 건물로 마을의 위치를 잡아 준다. 기존 수로·물 반사·수면 색상은 눈 덮인 사면과 불투명한 눈 표면으로 교체한다.
- **눈의 상태** — 흐르는 눈은 불규칙한 전면과 옆으로 퍼지는 눈가루로 표현한다. 정지층은 무광 표면과 남은 능선으로 표시한다. 흰 설면 위에서 두 상태의 경계를 명암과 움직임으로 식별할 수 있어야 한다.
- **조작과 위험 표시** — 유효·무효 배치 색, 금색 목표 카드, 준비 완료와 결과 화면은 공통 UI 관례를 따른다. 발원부·중심 진행 방향·배치 금지 구역을 준비 단계에 표시한다. 시민 위험은 아이콘과 수치로도 보여 주며, 실패 후에는 마지막 위험 위치와 파손 위치를 구분한다.
- **카메라와 소리** — 직교 전체 보기에서 능선과 마을을 함께 보여 준다. 구역 버튼은 해당 시민에게 카메라를 이동시킨다. 시작은 바람과 경보음, 방출 직전은 낮은 진동음, 충돌은 눈과 구조물의 다른 소리로 들려준다. 눈가루나 화면 흔들림이 배치와 결과 표시를 가리지 않게 한다.

| --- | --- |
| 스테이지 데이터와 필수 목표 | 공통 `GuardWaveStageInfoFile`로 `StageInfo.json`을 읽는다. 현재 마지막 `citizen` 항목의 `target: true`, 수량 6과 공통 목표 완료 판정을 사용한다. 눈사태 구현 시 `disasterName`과 자재 수량을 위 기획에 맞게 조정한다. |
| 팔레트·준비 완료·안내·결과 | `GuardWaveHud`에서 공통 카드·버튼·팝업 표시를 씬별 상태와 명령을 받도록 분리한다. 화면은 자재·잔량·목표 여부·준비 가능 여부·재해 단계·결과를 받고, 선택·준비 완료·복원·메뉴 복귀를 각 씬에 전달한다. 기존 `GuardWaveHud`의 `GuardWaveGame`·Fog 전용 참조를 이 경계로 직접 넘기지 않는다. Avalanche의 IMGUI는 공통 화면으로 옮기고 구역별 위험·적설 표시만 전용 패널로 연결한다. |
| 시간과 단계 | 이미 공유하는 `StagePreparationClock`을 사용한다. 준비 완료를 눌렀을 때 편집 이력을 확정하고 준비→재해 진행→결과 순서로 화면에 전달한다. Avalanche의 5초 경보와 종료 기준은 씬 로직이 제공한다. `GuardWaveStageTimer`의 Fog·Lava 표시 규칙은 각 스테이지에 둔다. |
| 직접 배치·회수·Undo | 공통 `StagePlacement`와 `StageEditHistory`를 사용한다. 공통 흐름은 미리보기 위치에 생성, 재고 차감, 편집 이력 기록, 회수와 재고 반환이다. Avalanche는 경사·시민 공간의 판정과 접합 블록 복원을 맡는다. 왼쪽 클릭 배치, Q/E 회전, Ctrl+Z 되돌리기를 공통으로 제공하며 기존 드래그 배치는 자재별 선택 사항으로 둔다. |
| 일시정지·카메라 | `StagePauseMenu`와 `StageCameraController`를 재사용한다. Esc, 휠 확대, 팝업을 통한 입력 차단과 메뉴 복귀 흐름을 맞춘다. 카메라 범위와 시민 위치 집중은 Avalanche 씬이 설정한다. |
| 스테이지 선택·클리어 기록 | `Scene.Avalanche`와 빌드 등록, `StageClearSession` 기록 경로는 이미 있다. `Game.unity`의 포스터 캐러셀에 Avalanche를 네 번째 항목으로 연결한다. `OutGameStageSelect`에 씬·이름·설명·포스터 연결을 한 항목으로 관리하고 다른 카드와 같은 클릭, 키보드 이동, 돌아왔을 때의 클리어 배지 흐름을 적용한다. 포스터 이름 제안은 `WHITE DESCENT`다. |

전역 씬 이동은 `Managers.Scene`을 사용한다. 재해 계산, 씬의 지형·카메라 설정, 시민 위험, 눈 가시화는 Avalanche 씬이 소유한다. 화면과 조작을 연결하기 위해 별도 전역 매니저를 추가할 필요는 없다.

## 7. 구현 순서와 인수 기준

1. **회색 박스** — 지형, 두 발원부, 양측 골짜기, 세 시민 구역을 배치한다. 빈 맵에서 눈이 마을에 도달하고 적어도 한 시민에게 실패가 발생해야 한다. 같은 초기 조건으로 세 번 실행해 첫 도착 위치와 실패 원인이 일관적인지 확인한다.
2. **방벽과 퇴적** — 움직이는 눈, 정지층, 콜라이더 투영과 하중을 연결한다. 비스듬한 방벽이 눈 방향을 바꾸고, 정면 방벽은 눈을 쌓아 올리며, 방벽이 파손되면 뒤따르는 눈이 틈을 통과해야 한다. 첫 방출의 퇴적이 두 번째 방출 시작 시 남아 있어야 한다.
3. **퍼즐과 재도전** — 두 갈래 유도와 한쪽 우회·보조 방벽을 각각 완성해 시민 6명을 지킬 수 있는지 확인한다. 시민 미배치, 시민 충돌, 시민 매몰의 메시지를 점검한다. 재도전 후 배치·접합·재고·시민이 일치하고 눈·위험도·시간이 초기화되는지 확인한다.
4. **공통 화면과 진입** — 포스터 → 준비 → 결과 → 스테이지 선택을 실제 입력으로 확인한다. 시간 제한 비활성 상태에서 자동 시작하지 않고, 일시정지 중에는 배치·눈·판정 시간이 진행되지 않아야 한다. 공통 UI를 수정한 후 Flood·Fog·Lava의 목표 배치, 준비 완료, 클리어 표시도 비교한다.
5. **아트·성능** — 최대 재고를 설치한 상태에서 두 번째 충돌 중 눈 계산, 메시 갱신, Rigidbody와 조인트 비용을 프로파일링한다. 기준 PC의 1080p 플레이어 빌드에서 60fps를 목표로 하고, 초과하면 메시 갱신 빈도와 장애물 투영 범위부터 줄인다. 준비 단계에는 흐르는 눈 계산을 실행하지 않는다.
