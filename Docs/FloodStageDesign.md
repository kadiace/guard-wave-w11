# Flood 스테이지 테마·룰·물리 요구 명세

- 작성일: 2026-11-17
- 상태: 재기획 제안 초안. 코드·씬·데이터에 아직 적용하지 않은 설계다.
- 대상: `Assets/Scenes/Flood.unity`
- 별도 구현: [Flood2 프로토타입과 플레이 검증 결과](Flood2Prototype.md). 기존 Flood에는 적용하지 않았다.
- 목적: 홍수와 시민 보호라는 플레이 목표를 먼저 정의하고, 그 목표에 필요한 물리를 준비한다.
- 수치 표기: 문서의 수치들은 별도 표시가 없으면 첫 프로토타입의 제안값이다. 플레이 검증 후 조정한다.

## 1. 한 문장 기획

**홍수가 덮쳐오는 강변 마을에서, 제한된 자재로 물길을 바꾸고 방벽을 보강해 시민 전원을 지킨다.**

플레이어는 물이 어디에서 오고 어디로 빠지는지 살펴본 뒤, 누구 앞에 어떤 구조물을 세울지 결정한다.
홍수가 시작되면 물의 움직임과 구조물의 버팀을 관찰하고, 실패 원인을 확인해 배치를 수정한다.
스테이지의 성과는 시민 개개인의 안전으로 보여준다.

### 핵심 경험

| 요소 | 플레이어가 느끼거나 판단할 내용 |
| --- | --- |
| 홍수의 예고 | 물이 오기 전까지 무엇을 준비할 것인가 |
| 세 곳의 시민 구역 | 한 구역을 막았을 때 다른 구역으로 물이 몰리지 않는가 |
| 구조물의 물성 | 가벼운 방벽을 어떻게 지탱하고 연결할 것인가 |
| 두 차례의 수위 상승 | 첫 홍수에서 드러난 약점을 두 번째 홍수까지 버틸 수 있는가 |
| 시민의 반응 | 내가 만든 구조물 덕분에 시민이 위험에서 벗어났는가 |

### 테마와 표현

- 배경은 비가 내리는 작은 강변 주거지다. 중앙의 하천과 낮은 마당, 갈라지는 수로가 한 화면에서 읽혀야 한다.
- 시민은 이웃을 부르거나 가방을 챙기고 서로 격려하는 모습으로 표현한다. 외형과 대사에 차이를 주되 초기 판정 규칙은 동일하게 둔다.
- 경고 방송, 멀리서 들리는 물소리, 상승하는 수위계, 젖는 지면으로 재해의 진행을 알린다.
- 구조물 뒤에서 물살이 약해지고 시민의 경고 표시가 사라지는 순간을 주요 보상으로 삼는다.
- 보호에 실패한 시민은 구조대의 도움이 필요한 상태로 표현한다. 과도한 신체 피해 연출은 사용하지 않는다.

| 구역의 생활 배경 | 시민과 주변 연출 |
| --- | --- |
| A: 강변 시장 마당 | 가게를 정리하던 상인과 물건을 전달하던 이웃이 함께 대기한다 |
| B: 작은 섬의 마을 광장 | 주민 두 명이 서로를 격려하며 마을의 상황을 살핀다 |
| C: 하류 도로의 버스 정류장 | 귀가하던 시민 두 명이 멈춘 교통수단 옆에서 구조를 기다린다 |

주민의 이름과 대사는 미술·서사 작업에서 붙인다. 보호 대상 ID와 위치는 대사 변경과 무관하게 유지한다.

## 2. 첫 구현에서 채택할 범위

### 기본 결정

1. 시민 6명을 세 구역에 2명씩 배치한다.
2. 시민은 지정된 위치에서 대기한다. 플레이어는 시민을 옮기거나 직접 조종하지 않는다.
3. 준비 단계에서만 구조물을 설치·제거·접합·경화한다. 홍수 진행 중에는 관찰과 일시정지만 허용한다.
4. 시민 6명 전원을 끝까지 보호해야 클리어한다.
5. 재료와 접합재가 제한되며, 물을 우회시키는 통로도 구조 설계의 일부가 된다.
6. 실패 후에는 홍수 직전의 배치로 복원해 수정하고 재도전한다.

이 범위에서는 대피 경로 찾기와 이동 AI를 요구하지 않는다. 먼저 물길과 구조물의 관계가 시민의
위험도에 일관되게 반영되는지 확인한다. 대피·이동식 구조대·수영·시민 운반은 후속 확장으로 둔다.

## 3. 플레이 흐름과 상태

| 상태 | 동작 | 종료 조건 |
| --- | --- | --- |
| 안내 | 시민 위치, 유입 방향, 두 차례 홍수와 자재 사용법을 보여준다 | 안내 닫기 |
| 준비 `Preparing` | 120초 동안 설치·제거·접합·경화·Undo를 허용한다 | 준비완료 또는 제한 시간 0초 |
| 경고 `Warning` | 편집을 잠그고 약 5초 동안 시민·물길을 보여준다 | 경고 시간 종료 |
| 홍수 `Flooding` | 정해진 유입 시퀀스를 실행하고 시민 위험도를 갱신한다 | 유입 시퀀스 종료 |
| 관찰 `Assessing` | 남은 물과 구조물 움직임, 시민 안전을 계속 관찰한다 | 성공 조건 또는 실패 조건 성립 |
| 성공 `Cleared` | 시민 전원 보호 결과와 배치 정보를 보여준다 | 스테이지 선택으로 복귀 또는 재시작 |
| 실패 `Failed` | 최초 실패 시민, 시각과 원인을 표시하고 편집을 잠근다 | 재도전 또는 스테이지 선택 |

- 준비완료와 타이머 만료는 동일한 시작 경로를 사용한다.
- 홍수 직전 입력을 종료하고 진행 중인 붓질·배치를 확정한 다음 체크포인트를 저장한다.
- 낙하 중인 자재는 경고 단계에서도 물리적으로 움직인다. 경고 중 추가 배치는 할 수 없다.
- 안내, 일시정지, 결과 화면에서는 준비 시간·홍수 시간·시민 위험도 갱신을 모두 정지한다.
- 시민 위험도 누적은 `Flooding`과 `Assessing`에서만 진행한다. 준비·경고 단계에는 낮은 기본 수위를 유지하고 시민은 안전 상태로 시작한다.
- 첫 버전은 하나의 준비와 하나의 두 차례 홍수로 구성한다. 현재 코드의 내부 5단계 진행을 새 룰로 가정하지 않는다.

## 4. 스테이지 공간 구성

### 제안 지도

```text
                         상류 / +Z
                      [넓은 유입 구간]
                             ↓
                         [수위계]
                             ↓
                 왼쪽 수로 ↙   ↘ 오른쪽 수로
          [A구역 시민 2명]       │
                      [B구역 시민 2명]
                      [중앙의 낮은 섬]   [C구역 시민 2명]
                 왼쪽 배수구 ↓   ↓ 오른쪽 배수구
                         하류 / -Z
```

### 좌표와 지형

좌표는 새 지도 설계를 위한 로컬 기준이다. 기존 씬의 바닥 높이나 절벽 좌표를 그대로 사용하는 명세가 아니다.

| 항목 | 첫 배치안 |
| --- | --- |
| 플레이 영역 | X = -18~18m, Z = 0~60m |
| 기본 지면 | Y = 0m |
| 하천 바닥 | Y = -1m 전후 |
| 상류 유입부 | Z = 54~60m, 중앙의 폭 약 12m |
| 주 수로 | 상류에서 Z = 32m까지 중앙으로 흐른다 |
| 수로 분기 | Z = 32m 부근에서 중앙 섬 양쪽으로 갈라진다 |
| 분기 수로 | X = -7m, +7m 부근을 따라 하류로 흐른다 |
| A 시민 구역 | 중심 X = -10m, Z = 26m, 지면 Y = 0.25m |
| B 시민 구역 | 중앙 섬 X = 0m, Z = 16m, 지면 Y = 0.35m |
| C 시민 구역 | 중심 X = 10m, Z = 14m, 지면 Y = 0.25m |
| 배수 경계 | Z = 0m의 열린 유출구. 역으로 물을 끌어당기는 힘은 사용하지 않는다 |

- 각 시민 구역은 약 3×3m다. 두 시민의 위치는 서로 겹치지 않게 고정한다.
- A와 C는 분기 수로의 넘침에, B는 두 수로 사이로 돌아 들어오는 물에 노출되도록 만든다.
- 지형 자체의 고저차가 읽혀야 한다. 예고 수위, 실제 수면, 시민 발밑 높이를 같은 기준으로 표시한다.
- 기존 절벽과 폭포는 첫 목표 지도의 필수 요소가 아니다. 하류 배수구가 시민 실패 경계와 동일한 개념이 되지 않도록 한다.
- 물리 도메인은 시민 구역까지 포함해야 한다. 현재 고정 폭 24m의 강물 도메인 밖에 시민만 추가해서는 안 된다.

### 확보해야 할 해법

- 시민 앞에 물을 나누는 사선 방벽을 세우고, 양옆으로 흐르는 통로를 남긴다.
- 가벼운 방벽 아래를 무거운 자재로 지지하고 접합해 들림·회전을 억제한다.
- 한 구역의 방어가 이웃 구역의 침수를 늘리는 상황을 보고 세 구역을 함께 조정한다.

맵의 고정 배수 능력은 유지한다. 무구조 배치에서는 일부 시민이 위험에 노출되고, 한 줄의 허술한
방벽은 두 번째 홍수에서 약점을 드러내며, 최소 두 종류의 배치 해법이 시민 전원을 보호할 수 있어야 한다.

## 5. 자재와 설치 규칙

### 첫 팔레트

| 자재·도구 | 제안 지급량 | 역할과 규칙 | 현재 구현과의 관계 |
| --- | --- | --- | --- |
| 방벽 패널 | 24개 | 평평한 면으로 물길을 나눈다. 가벼워 들리거나 돌아갈 수 있다 | 새 프리팹·충돌 형상 필요. 기존 통나무의 부유·배치 시스템 재사용 후보 |
| 무거운 돌 | 18개 | 방벽의 지지와 무게추 역할. 개별 돌 사이 틈은 물이 통과할 수 있다 | `forest_pebble`의 침강·접착 기능 재사용 후보 |
| 접합재 | 30m 상당 | 물체 표면에 바르면 접촉한 자재를 연결한다 | 기존 `mud` 기능에 사용량 제한과 테마 표현 추가 |
| 경화 도구 | 횟수 제한 없음 | 선택한 젖은 도포 획을 약 1초 동안 경화한다 | 기존 `hair_dryer` 기능 재사용 후보 |

- 팔레트는 네 항목으로 시작한다. 패널 크기는 길이 3.6m·높이 1.2m·두께 0.6m를 첫 검증값으로 둔다.
- 위 치수는 현재 0.6m 격자에서 검증하기 위한 시작점이다. 방수 형상과 조작성을 확인한 뒤 최종 크기를 정한다.
- 패널의 상대 밀도는 0.6, 돌은 2.6을 첫 후보로 삼는다. 질량·마찰·접합 강도는 새 지도에 맞춰 다시 조정한다.
- 설치는 중력과 충돌에 따라 정착한다. 승인되지 않은 관통 상태를 그대로 확정할 수 없다.
- 시민의 대기 캡슐 주변 0.2m 여유 공간에는 새 자재를 놓을 수 없다. 이 공간과 설치 불가 이유를 미리 보여준다.
- 시민·고정 지형·건물은 제거할 수 없다. 자유 배치 영역과 고정 구조물의 경계를 표시한다.
- 준비 단계의 자재 제거는 해당 자재를 반환한다. Undo는 배치와 자원 사용량을 함께 되돌린다.
- 홍수 중 유실·파손된 자재는 해당 시도 안에서 반환하거나 재설치하지 않는다. 실패 복원에서는 준비 체크포인트의 재고로 돌아온다.

### 접합재 사용량

- 유효한 도포 제스처를 시작할 때 0.5m 상당을 소비하고, 실제로 추가된 도포 궤적의 월드 길이만큼 더 소비한다.
- 표면 변화나 내부 샘플 제한으로 같은 제스처가 여러 패치로 나뉘어도 시작 비용을 다시 부과하지 않는다.
- 도포되지 않은 구간과 같은 위치의 중복 입력에는 길이 비용을 추가하지 않는다. 새 제스처의 겹칠에는 시작 비용이 든다.
- 잔량이 부족하면 그 지점에서 도포를 종료한다. 이미 만들어진 젖은 영역과 기존 연결은 유지한다.
- 사용량과 잔량은 도포 중에 표시하고, Undo·실패 복원에 포함한다.

### 연결과 경화

- 첫 버전은 자재 하나가 생성하는 접착 조인트를 시도당 최대 하나로 제한하는 현재 규칙을 유지한다.
- 이미 고정된 자재의 젖은 표면에는 다른 새 자재가 붙을 수 있다. 이를 통해 가지 형태의 구조물을 만들 수 있다.
- 여러 면을 모두 독립적인 조인트로 연결하는 기능은 첫 버전의 필수 요구가 아니다. 현재 연결 관계를 화면에서 확인할 수 있어야 한다.
- 연결이 파손된 자재는 그 시도에서 다시 붙지 않는다. 자동 재접착으로 무한히 버티는 상태를 만들지 않는다.
- 경화하면 해당 획의 기존 연결 강도와 토크 한계가 한 번만 2배가 되고, 그 획은 새 접착을 받지 않는다.
- 같은 위치를 여러 번 칠해도 방수 성능이나 조인트 강도가 무한히 증가하지 않는다. 도포는 물체 사이의 연결을 만든다.
- 접합된 두 자재의 틈이 넓으면 물이 샐 수 있다. 연결 표시만으로 방수 성공을 판정하지 않는다.

## 6. 시민 규칙

### 역할과 구현 범위

첫 버전의 시민은 지정 위치의 보호 대상과 물 노출 판정 영역으로 구성한다.
대기 애니메이션이 판정 위치를 이동시키지 않으며, 시민은 물체 배치 시스템의 자재가 아니다.

시민을 직접 유체 충돌체로 등록하지 않는다. 시민 몸이 물을 밀어내면서 자기 노출을 감지하지 못하는
문제를 피하고, 보호 구조물이 시민 주변의 실제 물을 줄이는 효과부터 검증한다.
시민의 물리적 떠밀림과 래그돌은 후속 기능이며 첫 버전의 성공·실패 조건에 포함하지 않는다.
낙하 자재의 충돌에 따른 별도 시민 피해도 후속 범위다. 첫 버전의 시민 위험은 물 노출로 판정한다.

### 시민 상태

| 상태 | 의미 | 표현 |
| --- | --- | --- |
| 안전 `Safe` | 유효한 관측에서 위험 조건이 없고 위험도도 낮다 | 평상시 대기, 작은 안전 표시 |
| 주의 `Warning` | 위험도 30 이상이거나 물의 위험 조건이 성립했다 | 노란 표시, 주변을 살피는 반응 |
| 위급 `Critical` | 위험도 70 이상 또는 심한 침수 | 빨간 표시, 도움 요청 |
| 구조 필요 `RescueRequired` | 위험도 100에 도달했다 | 보호 실패 표시, 구조 요청 연출 |
| 보호 완료 `Protected` | 스테이지 성공 시 해당 시민의 최종 상태 | 안도·감사 반응 |

표현 상태는 위험도가 내려가면 완화할 수 있다. `RescueRequired`는 해당 시도의 종료 상태이므로
자연 회복시키지 않는다. 시민끼리의 외형 차이는 초기 위험 판정이나 인내 시간에 영향을 주지 않는다.

### 노출 관측

시민마다 발 위치·판정 반경·높이를 정의한다. 첫 값은 반경 0.4m, 높이 1.5m다.
시민 주변의 실제 물 점유와 유속을 관측하며, 가장 높은 물방울 한 개를 수면으로 취급하지 않는다.

| 관측 값 | 의미 |
| --- | --- |
| `EffectiveDepth` | 발 위치를 기준으로 실제 물이 지속적으로 차 있는 유효 수심 |
| `HorizontalFlowSpeed` | 해당 물이 있는 위치에서의 수평 유속 크기 |
| `WetCoverage` | 시민 판정 영역 주변에서 실제 물이 확인된 비율 |
| `SampleAge` | GPU 관측 시점부터 지난 시간 |
| `SampleValid` | 현재 위험도 판정에 사용할 수 있는 관측인지 여부 |

- 최소한 중앙과 주변 여러 지점, 높이별 물 점유를 함께 본다. 지점 수와 가중치는 물리 검증에서 결정한다.
- 물 점유가 거의 없는 날리는 물방울, 폭포 입자, 시민과 다른 높이의 얇은 물층이 시민을 완전히 잠긴 것으로 만들면 안 된다.
- 첫 `WetCoverage` 인정 기준은 0.25로 둔다. 이 값은 유효 수심과 실제 물 점유를 함께 검증해 조정한다.
- 관측은 약 10Hz로 묶어 전달한다. 같은 관측을 새 관측처럼 중복 소비하지 않는다.
- 최신 관측이 0.5초 이상 지연되면 위험도 증가·회복과 성공 대기를 모두 보류하고 재동기화한다.
  전체 시뮬레이션과 90초 관찰 제한의 진행도 일시 정지하고, 관측 복구 처리는 계속 허용한다.
  실시간 5초 안에 복구하지 못하면 기술 오류로 재시도하며 시민의 게임상 실패로 계산하지 않는다.

### 위험도 계산

위험도 `Exposure`는 시민마다 0~100으로 관리한다.

| 조건 | 위험도 변화 제안값 |
| --- | --- |
| 유효 수심 0.45m 이상 | 초당 +12.5 |
| 유효 수심 0.20m 이상이며 수평 유속 2m/s 이상 | 초당 +12.5 |
| 유효 수심 1.1m 이상 | 초당 +25 |
| 안전 조건이 0.75초 이상 지속 | 초당 -10 |
| 관측 무효·일시정지·결과 화면 | 변화 없음 |

- 위 위험 조건들은 `WetCoverage` 인정 조건을 만족할 때만 사용한다. 동시에 성립하면 가장 큰 증가율 하나를 사용한다.
- 위험 진입은 0.2초의 연속 유효 관측으로 확정한다. 이 확인 시간은 위험도에 소급해 중복 가산하지 않는다.
- 회복 중 위험 조건이 다시 성립하면 회복을 즉시 중단하고 위험 진입 확인을 다시 수행한다.
- 표의 값은 한 순간의 튐을 허용하면서 지속적인 침수는 실패로 이어지게 하는 게임 규칙이다.
  첫 일반 위험 조건에서 0부터 100까지 약 8초가 걸리므로 첫 홍수의 경고와 두 번째 홍수의 압박을 구분할 수 있다.
- 마커 색에는 히스테리시스를 둔다. 예를 들어 위급 진입은 70, 해제는 60으로 하여 표시가 떨리지 않게 한다.

## 7. 홍수 시퀀스

### 입력과 진행

유입은 두 차례 수위 상승과 그 사이의 완화 구간으로 구성한다. 정상 진행에서 방향과 강도에 무작위성을 추가하지 않는다.

| 경고 종료 후 시각 | 상류 유입 입력 | 기획 의도 |
| --- | --- | --- |
| 0~4초 | 낮은 유량에서 첫 홍수로 증가 | 물길과 구조물 반응을 읽을 시간 |
| 4~11초 | 첫 고수위 유지 | 약한 연결, 들리는 패널과 새는 틈을 드러냄 |
| 11~16초 | 유량 감소 | 위험도가 일부 회복되고 다음 홍수를 예고 |
| 16~24초 | 두 번째 고수위 | 첫 홍수에서 약해진 구조물을 다시 압박 |
| 24~32초 | 유입을 서서히 종료 | 관찰·평가 단계로 연결 |

이는 **상류 입력 시간표**다. 시민 구역 도착 시각과 같다고 가정하지 않는다.
파도가 시민에게 도착하는 시각은 수로 길이, 흐름과 방어 배치에 따라 달라진다.

첫 입력 후보는 상류 바닥 기준 수심 1.7m / 2.1m, 평균 진행 유속 약 3m/s다.
현재 설정의 평상시 유속 20m/s와 추가 파고 3m를 새 지도의 기본값으로 그대로 이식하지 않는다.

### 유입 종료와 잔류 물

- 유입 종료 후에도 이미 들어온 물, 부유 자재, 무너지는 구조물과 시민 위험도는 계속 계산한다.
- 물을 저장하는 방벽도 유효한 해법이다. 안전한 위치의 정체수까지 모두 사라져야 성공하는 규칙은 두지 않는다.
- 다음 조건을 모두 만족할 때 홍수 종료가 확인된 것으로 본다.
  1. 두 번째 홍수의 유입과 감쇠가 끝났다.
  2. 마지막 유입 후 최소 관찰 시간이 지났다. 첫 후보는 25초이며, 맵에서 후미 도달을 확인해 보정한다.
  3. 플레이 영역의 유효 물 체적 중 빠르게 움직이거나 수위가 변하는 물의 비율이 충분히 작다.
     첫 안정 기준은 속도 0.5m/s 또는 수면 변화율 0.1m/s를 넘는 체적 비율이 5% 미만으로 3초 유지되는 것이다.
- 물리 검증에서 마지막 파도나 측면 유입을 놓치는 사례가 나오면 관찰 시간과 안정 기준을 함께 보정한다.
  경과 시간만으로 성공시키지 않는다.
- 준비완료 후 90초까지 안정·성공 조건을 만족하지 못하면 `잔류 침수/불안정` 사유로 해당 시도를 종료한다.

## 8. 성공·실패와 복원

### 성공

아래 조건을 모두 만족하면 시민 6명을 `Protected`로 바꾸고 클리어한다.

- 홍수 종료가 확인됐다.
- 구조 필요 상태가 된 시민이 없다.
- 시민 전원이 유효 관측에서 위험 조건 없이 5초 동안 유지됐다.

위험도는 반드시 0일 필요가 없다. 실제 위협이 해소되고 시민 모두 생존 범위에 있는 것이 기준이다.
별도의 단계 이동이나 이후 파도는 성공 처리 뒤 자동으로 발생하지 않는다.

### 실패

- 시민 한 명이라도 `Exposure = 100`이 되면 즉시 보호 실패를 확정한다.
- 제한된 관찰 시간 안에 성공 조건을 만족하지 못하면 잔류 위험 실패로 확정한다.
- 시민이 실패하기 전에 구조물이 파손되는 것은 허용한다. 구조물의 생존 자체는 독립적인 패배 조건이 아니다.
- 현재 깃발 위치와 절벽 경계 조건은 새 Flood의 성공·실패 조건에서 시민 판정으로 교체한다.

### 실패 피드백

- 최초 실패 시민과 구역을 강조한다.
- 실패 시점, 최대 수심, 당시 유속, 위험 노출 지속 시간을 표시한다.
- 최근 구조물 파손, 넘침 또는 측면 유입처럼 실제 관측한 사건을 표시한다.
  원인을 추정할 근거가 없으면 특정 구조물을 실패 원인으로 단정하지 않는다.
- 재도전 시 시민·구조물·접합·건조 상태·재료 재고·접촉 캐시·유체 초기 상태를 준비 체크포인트로 복원한다.
- GPU에서 늦게 도착한 이전 시도의 물 관측과 힘이 복원 직후 적용되지 않도록 시도 ID로 폐기한다.

| 팔레트 | 남은 패널·돌 수, 접합재 잔량, 경화 상태 |
| 설치 미리보기 | 최종 예상 위치, 유효/불가 여부와 불가 사유 |

- 높은 물과 구조물에 시민이 가려져도 위치와 위험 마커는 읽을 수 있어야 한다.
- 물길 화살표는 준비 단계의 지도상 예고와 실행 중 실제 유속 표시를 구분한다.
- 카메라 이동·회전·확대는 관찰 중에도 허용한다. 시민 위치로 이동하는 버튼을 제공한다.
- 경화 전에는 해당 획이 더 이상 새 자재를 붙이지 않게 된다는 안내를 보여준다.
- 성공·실패 판정과 팝업은 시도당 한 번만 발생한다.

## 10. 필요한 물리와 데이터 계약

### 시스템별 요구

| 시스템 | 필요한 동작 | 검증 기준 |
| --- | --- | --- |
| 물의 이동 | 갈라진 수로·건조한 땅·시민 구역을 포함해 유입, 넘침, 배수 표현 | 빈 맵의 흐름과 예고 방향이 일치 |
| 물과 방벽 | 패널이 막으면 물이 우회·누적·넘치고 틈으로 통과 | 보호한 곳 뒤의 관측 수심/유속이 변함 |
| 물과 자재 | 패널은 들림·미끄러짐·회전, 돌은 침강과 바닥 마찰 반영 | 질량·상대 밀도·지지가 행동 차이를 만듦 |
| 자재 연결 | 접점의 힘·토크가 한계를 넘으면 파손 | 물이 닿았다는 이유만으로 임의 파손하지 않음 |
| 시민 위험 관측 | 실제 물 점유, 수심, 유속과 관측 유효성 제공 | 물방울 한 개나 빈 공간 아래의 가상 수면으로 위험도가 증가하지 않음 |
| 시도 복원 | 물·조인트·자원·시민 상태와 비동기 결과의 세대 관리 | 이전 시도 결과가 복원 상태에 섞이지 않음 |

### 규칙과 물리의 경계

- 시민 룰은 물리 시스템이 전달한 관측으로 위험도를 계산한다. 렌더링 색이나 화면상의 물 윤곽을 판정에 사용하지 않는다.
- 물리 시스템은 시민의 성공 여부를 결정하지 않는다. 관측과 힘을 제공하고, 스테이지 룰이 시간·위험도·종료를 결정한다.
- 유체 방식은 현재 FLIP/APIC를 재사용할 수 있지만, 먼저 위 데이터 계약을 충족하는지 확인한다.
  전체 솔버 교체를 선행 조건으로 두지 않는다.
- 시민을 숨은 불가침 벽으로 만들거나, 보호 구역의 물을 시각적으로만 제거해 성공시키지 않는다.
- 조악한 격자로 표현되지 않는 틈을 정밀하게 판정하는 것처럼 약속하지 않는다. 방벽 치수·충돌 프록시·격자 해상도를 함께 조정한다.
- 현재 격자 압력, 단순화된 충돌체와 게임용 파봉 지지력의 한계는 새 지형에서 다시 확인한다.

| 홍수 시퀀스 | 유입 시간표, 높이·유량·속도, 종료 감시와 제한 시간 |
| 재료 카탈로그 | 프리팹, 재고, 질량·밀도·마찰, 접합 가능 여부, 설명 |
| 시도 체크포인트 | 배치·활성 상태·Rigidbody 상태·연결·건조·자원·시민 상태·시도 ID |

이름은 설계상 구분이며 새 클래스 생성이 확정된 것은 아니다. 씬별 참조는 씬 컨텍스트에 두고,
전역 기능이 필요할 때만 프로젝트의 Managers 정적 접근 패턴과 Core/Contents 구분을 따른다.

## 11. 성능 예산과 공정성

첫 검증 예산은 시민 6명, 배치 자재 42개, GPU 충돌 프록시 128개 이내로 둔다.
접착 조인트는 배치 자재 수에 따라 상한이 정해지고, 진흙은 우선 96패치·128트리거 이내를 목표로 관리한다.
이 상한은 처음부터 사용자 입력을 조용히 무시하는 하드 제한으로 구현하지 않는다.
도달 시 명시적인 잔량 안내와 종료 처리가 필요하며, 접착 범위를 축소해 장면을 억지로 맞추지 않는다.

- 물·시민 관측·조인트 이벤트는 묶어서 처리한다. 시민마다 별도의 GPU 왕복 요청을 만들지 않는다.
- 기존 진흙 최적화의 조기 제외, 동일 틱 중복 방지, 건조 트리거 비활성화를 유지한다.
- 배포 기본 상태에서는 물체별 힘의 매 틱 로그를 끈다. 진단은 필요할 때만 켠다.
- Ready 전 준비, 첫 홍수, 두 번째 홍수, 구조물 붕괴와 복원을 각각 측정한다.
- 목표 기기와 해상도는 별도로 확정한다. 첫 기준 후보는 RTX 4060 / 1080p이며,
  실제 Standalone에서 60fps를 목표로 CPU·GPU p95 프레임 시간과 물리 몰림을 함께 측정한다.
- 입자 수·압력 반복 수는 화면 품질만으로 정하지 않는다. 시민 위험 판정과 방벽 차폐가 유지되는 범위에서 정한다.
- 같은 초기 배치와 시퀀스의 반복 결과가 판정 임계값 주변에서 흔들리지 않아야 한다.
  GPU 계산의 비트 단위 결정성을 전제로 하지 않고, 관측 유지 시간과 판정 여유로 공정성을 확보한다.

## 13. 제작 순서와 완료 기준

| 단계 | 산출물 | 다음 단계로 넘어갈 기준 |
| --- | --- | --- |
| 1. 회색 지도와 시민 목표 | 수로·세 구역·시민 표시·준비/결과 흐름 | 목표와 물의 방향을 설명 없이도 읽을 수 있음 |
| 2. 빈 맵 유체 검증 | 유입·분기·넘침·배수·시민 관측 | 빈 맵에서 위험이 생기고 물방울·관측 지연으로 오판하지 않음 |
| 3. 최소 구조물 검증 | 패널·돌·접합·경화 | 구조물을 놓은 위치에 따라 위험도에 설명 가능한 차이가 발생 |
| 4. 룰과 복원 통합 | 두 차례 홍수·전원 보호·실패 피드백·체크포인트 | Undo·재도전·일시정지 후 자원·시민·연결·물 상태가 일치 |
| 5. 표현과 성능 조정 | 시민 반응·수위 예고·마커·성능 기록 | 가림 없이 판단 가능하고 목표 기기에서 예산을 충족 |

확인은 Unity Play Mode와 Standalone의 직접 플레이·성능 측정으로 수행한다.
이 문서는 프로젝트 원칙과 별개인 자동 테스트 코드 작성을 요구하지 않는다.

### 필수 플레이 확인 항목

1. 무구조 상태에서는 시민에게 위험이 발생하고, 첫 경고를 본 뒤 두 번째 홍수가 더 위협적이라고 느껴진다.
2. 올바른 구조물을 설치하면 물의 실제 경로와 시민 위험도가 함께 달라진다.
3. 동일 자재 예산 안에서 시민 전원을 보호하는 해법이 최소 두 가지 있다.
4. 전면을 막아 생긴 역류나 넘침이 다른 구역에 영향을 주며 그 이유를 화면에서 확인할 수 있다.
5. 높은 곳의 물방울, 얇은 물층과 GPU 관측 지연만으로 시민이 구조 필요 상태가 되지 않는다.
6. 준비 종료 후 들어온 마지막 위협이 도착하기 전에 조기 클리어하지 않는다.
7. 안전한 곳에 물을 저장한 해법도 유입 종료와 안정 조건을 만족하면 클리어할 수 있다.
8. 실패 복원과 Undo 후 경화·재고·시민 위험도·접촉 상태가 맞고, 이전 시도의 비동기 결과가 섞이지 않는다.
9. 같은 배치와 유입을 여러 번 실행했을 때 성공·실패가 일관된다.
10. 자재와 진흙을 많이 사용한 상태에서도 접착 콜백과 물리 업데이트가 누적되어 긴 멈춤을 만들지 않는다.

## 14. 첫 프로토타입 이후 결정할 사항

- 시민 6명과 세 구역이 한 화면에서 읽히는지, 먼저 두 구역으로 시작할 필요가 있는지.
- 패널과 돌의 크기·수량 및 접합재 30m가 물길 우회와 보강을 모두 가능하게 하는지.
- 시민 위험도를 수치로 항상 보여줄지, 기본 마커와 선택 상세로 충분한지.
- 제한 시간 120초가 첫 시도의 이해와 재도전의 속도에 맞는지.
- 서로 다른 지도·재료 예산·유입 패턴으로 후속 난도를 만들지. 첫 버전에는 난수 증가를 넣지 않는다.
- 시민 이동·대피와 물리적 떠밀림을 추가할지. 추가한다면 이동 경로·지지·구조 가능 상태부터 별도 룰로 정의한다.

이 항목들이 확정되기 전에도, 문서의 기본안으로 첫 회색 지도와 물리 검증을 시작할 수 있다.
